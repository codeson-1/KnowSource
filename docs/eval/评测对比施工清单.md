# 评测对比施工清单（vector vs hybrid）

> **目标**：跑出两种检索模式的真实对比数据，并强化指标让差异显现，回填简历。
>
> **原则**：零业务代码改动，只在 `eval` 包内闭环。`ChatService`、`ChatRequest`、`RetrievalService`、`RetrievalMode`、`EvalController`、`application.yml` 全部不动。检索模式切换靠手动改配置文件，不改任何代码。
>
> **预估工作量**：1-2 天。
>
> **现状关键事实**（已核实）：
> - 现有指标 `recallAt5 = citationHits / inScope`，而 `citationHit` 只判断「来源文档标题是否包含期望文档」，**测不出 ranking 质量差异**（vector 和 hybrid 很可能都是 100%）。
> - `retrievalService.resolveMode(null)` 兜底用配置默认值 `hybrid`，所以改 `application.yml` 即可全局切换检索模式，代码不用动。
> - `EvalRunnerService.runGoldenSet()` 和 `ask()` 保持原样不动，不传 retrievalMode，让它自动读配置。

### 步骤 4：改造判定逻辑（第 2 天，核心，1.5 小时）

**文件**：`EvalRunnerService.java`

> ⚠️ **前置确认点**：`ChatResponse` 是否有 `answer()` 字段？若有直接用；若无，需要走 traceId 查 `qa_traces.answer`。**施工前先确认，决定 extractAnswer 走哪条路径。**

#### 4.1 `toCaseResponse()` 增加三级判定

**只改这一个方法**，不碰 `ask()`、不碰 `askGoldenCase()`、不碰 `runGoldenSet()`。方法签名保持不变，在现有代码基础上追加三块逻辑：关键词命中判定、文档排名计算、新字段填回。

```java
private EvalCaseResponse toCaseResponse(GoldenCase goldenCase, ChatResponse response) {
    List<String> sourceTitles = response.sources().stream().map(SourceCitation::title).toList();

    // 现有判定（保留不动）
    boolean citationHit = !goldenCase.outOfScope()
            && goldenCase.expectedDocTitle() != null
            && sourceTitles.contains(goldenCase.expectedDocTitle());
    boolean refusalCorrect = goldenCase.outOfScope() == response.refused();
    boolean passed = goldenCase.outOfScope() ? refusalCorrect : citationHit && !response.refused();
    String expected = goldenCase.outOfScope() ? EXPECTED_REFUSAL : goldenCase.expectedDocTitle();

    // —— 新增：关键词命中（基于答案文本）——
    String answerText = extractAnswer(response);
    String matchedKeyword = goldenCase.expectedKeywords().stream()
            .filter(kw -> answerText != null && answerText.contains(kw))
            .findFirst().orElse(null);
    boolean keywordHit = matchedKeyword != null;

    // —— 新增：文档排名（1-based）——
    int docRank = 0;
    if (goldenCase.expectedDocTitle() != null) {
        for (int i = 0; i < sourceTitles.size(); i++) {
            if (sourceTitles.get(i).equals(goldenCase.expectedDocTitle())) {
                docRank = i + 1;
                break;
            }
        }
    }

    return new EvalCaseResponse(
            goldenCase.id(), goldenCase.setupQuestion(), goldenCase.question(),
            goldenCase.profile(), expected, response.refused(), sourceTitles,
            citationHit, refusalCorrect, passed, response.qaTraceId(), response.sessionId(),
            keywordHit, matchedKeyword, docRank);   // ← 新增 3 字段
}
```

#### 4.2 新增 `extractAnswer()` 方法

```java
private String extractAnswer(ChatResponse response) {
    if (response.answer() != null && !response.answer().isBlank()) {
        return response.answer();
    }
    return jdbcClient.sql("SELECT answer FROM qa_traces WHERE id = :id")
            .param("id", response.qaTraceId())
            .query(String.class)
            .optional()
            .orElse("");
}
```

#### 4.3 `summarize()` 增加三项指标

```java
private EvalSummaryResponse summarize(List<EvalCaseResponse> results) {
    int inScope = (int) results.stream().filter(r -> !EXPECTED_REFUSAL.equals(r.expected())).count();
    int outOfScope = results.size() - inScope;

    long citationHits = results.stream().filter(EvalCaseResponse::citationHit).count();
    long refusalCorrect = results.stream()
            .filter(r -> EXPECTED_REFUSAL.equals(r.expected()))
            .filter(EvalCaseResponse::refusalCorrect)
            .count();
    double citationRate = inScope == 0 ? 0.0d : (double) citationHits / inScope;
    double refusalAccuracy = outOfScope == 0 ? 0.0d : (double) refusalCorrect / outOfScope;

    // —— 新增指标计算（仅对 inScope 用例）——
    List<EvalCaseResponse> inScopeResults = results.stream()
            .filter(r -> !EXPECTED_REFUSAL.equals(r.expected()))
            .toList();

    long keywordHits = inScopeResults.stream().filter(EvalCaseResponse::keywordHit).count();
    double keywordHitRate = inScopeResults.isEmpty() ? 0 : (double) keywordHits / inScopeResults.size();

    // MRR = mean(1/docRank)，未命中 docRank=0 贡献 0（标准定义，不跳过未命中）
    double mrr = inScopeResults.stream()
            .mapToDouble(r -> r.docRank() > 0 ? 1.0 / r.docRank() : 0.0)
            .average().orElse(0);

    // 平均排名（仅算命中的）
    double meanDocRank = inScopeResults.stream()
            .mapToInt(EvalCaseResponse::docRank)
            .filter(rank -> rank > 0)
            .average().orElse(0);

    return new EvalSummaryResponse(
            results.size(), inScope, outOfScope, citationRate, citationRate, refusalAccuracy,
            keywordHitRate, mrr, meanDocRank);   // ← 新增 3 字段
}
```

## 三、执行流程（跑数据时）

```bash
# 1. 确保环境
docker compose up -d              # 起 PostgreSQL
# 配好 .env（AI_DASHSCOPE_API_KEY）

# 2. 清理旧评测数据（重要！种子文档加了新字段后必须重新建库）
#    在数据库管理工具中删除旧的「评测知识库」及关联文档，或手动删库：
#    docker compose exec postgres psql -U knowsource -c "DROP DATABASE IF EXISTS knowsource_eval;"
#    （具体库名以实际为准）

# 3. 第一轮：纯向量检索
#    ① 修改 application.yml，将检索模式设为 vector
#    ② 启动服务
#    ③ 调评测接口（需登录拿 ADMIN token）
curl -X POST http://localhost:8080/api/eval/golden-set/run \
  -H "Authorization: Bearer <ADMIN_TOKEN>"
#    ④ 保存生成的报告，重命名为 vector-report.md
cp docs/eval/report.md docs/eval/vector-report.md

# 4. 第二轮：混合检索
#    ① 修改 application.yml，将检索模式改回 hybrid
#    ② 重启服务
#    ③ 再调一次评测接口
curl -X POST http://localhost:8080/api/eval/golden-set/run \
  -H "Authorization: Bearer <ADMIN_TOKEN>"
#    ④ 保存报告，重命名为 hybrid-report.md
cp docs/eval/report.md docs/eval/hybrid-report.md

# 5. 手动对比两份报告
#    打开 vector-report.md 和 hybrid-report.md，重点看三组数字：
#    - keywordHitRate：答案含期望关键词的比例
#    - MRR：平均倒数排名
#    - meanDocRank：期望文档平均排名
```

**注意**：两次跑的是**同一个 eval KB**（代码已有 `findOrCreateEvalKb` 复用逻辑），所以 vector 和 hybrid 面对的是完全相同的文档和向量，**对比公平**。但种子文档变动后第一次跑前**必须清库**，否则旧文档还在。

## 五、风险与回退

| 风险 | 应对 |
|---|---|
| vector 和 hybrid 差异不大 | 重点看精确检索用例的 `docRank` 和 `keywordHit`，这两个指标对 ranking 质量敏感，即使都召回也会有差异 |
| `ChatResponse` 没有 answer 字段 | 用 qaTraceId 查 `qa_traces.answer`（步骤 4.2 的 extractAnswer 已给兜底方案） |
| `findOrCreateEvalKb` 复用旧 KB，但种子文档变了 | **第一次跑前手动清理旧的「评测知识库」**，否则新字段不会生效 |
| 报告写不进磁盘（容器/jar 环境） | 本地 Maven 跑没问题；容器环境改用配置项 |
